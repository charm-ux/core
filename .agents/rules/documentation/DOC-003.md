# DOC-003: Follow the component `.mdx` docs-page structure

Component docs pages (`packages/docs/src/content/docs/components/<name>.mdx`) follow a
consistent shape so the docs site reads uniformly. Match it:

1. **YAML frontmatter** with a `title:`.
2. **Import `ComponentMetadata.astro`** and render it (name/status/since sourced from the
   manifest).
3. A one-line **intro** followed by a live example in a `<code-bubble>` block.
4. **`## Best Practices`** — bolded **_Do_** / **_Don't_** bullet lists (for components with
   usage guidance).
5. **`## Examples`** — `###` sub-sections, each wrapping an HTML snippet in `<code-bubble>`
   to render it live. (Some pages instead use one `##` per attribute/feature.)
6. A terminal **`## API`** heading — the props/events/slots/parts table is generated from
   the custom-elements manifest ([CHARM-005](../internal/CHARM-005.md)); don't hand-write
   an API/props table in prose.

**Do:**

```mdx
---
title: Tooltip
---

import ComponentMetadata from '../../../components/ComponentMetadata.astro';

<ComponentMetadata name="tooltip" />

Tooltips display contextual information on hover or focus.

<code-bubble>
  <ch-tooltip content="Save">...</ch-tooltip>
</code-bubble>

## Best Practices

**_Do_**

- Keep tooltip text short.

**_Don't_**

- Put interactive content inside a tooltip.

## Examples

### Placement

<code-bubble> ... </code-bubble>

## API
```

**Don't:**

- Hand-maintain a props table in the `.mdx` (it duplicates and drifts from the generated
  `## API`).
- Skip the live `<code-bubble>` examples or the `ComponentMetadata` header.
