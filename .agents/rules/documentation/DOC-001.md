# DOC-001: Provide Storybook stories via `getStorybookHelpers`

Every component ships a `<name>.html.stories.ts` file for the `@storybook/web-components-vite`
Storybook. Derive `args`, `argTypes`, `events`, and `template` from
`getStorybookHelpers('<scoped-tag>')` (`@wc-toolkit/storybook-helpers`) so controls and
action logging stay generated from the custom-elements manifest
([CHARM-005](../internal/CHARM-005.md)) — don't hand-maintain `argTypes`. Import the
component's `index.js` (and any dependencies) so it registers, and render stories through
`template(args)`.

**Do:**

```ts
import { Meta, StoryObj } from '@storybook/web-components-vite';
import { getStorybookHelpers } from '@wc-toolkit/storybook-helpers';
import './index.js';
import type { CoreButton } from './index.js';

const { args, argTypes, events, template } = getStorybookHelpers('ch-button');

const meta: Meta<CoreButton> = {
  title: 'Core/Button',
  component: 'ch-button',
  args,
  argTypes,
  parameters: { actions: { handles: events } },
};
export default meta;

type Story = StoryObj<CoreButton & typeof args>;

export const Default: Story = {
  render: args => template(args),
  args: { 'default-slot': 'Button' },
};
```

**Don't:**

```ts
// Hand-written argTypes drift from the manifest; raw innerHTML skips the helpers' template.
const meta = {
  component: 'ch-button',
  argTypes: { type: { control: 'text' } }, // stale the moment the prop union changes
};
export const Default = { render: () => '<ch-button>Button</ch-button>' };
```
