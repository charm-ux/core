# I18N-001: Render user-facing text via slots and DOM, not attributes

Human-readable text is the consumer's to provide and translate. Expose it through slots
(preferred, [COMP-001](../component-design/COMP-001.md)) or as DOM text nodes — never bake
display strings into the component, and avoid designing APIs where the only way to set
visible copy is a string attribute the consumer must translate through your prop surface.
Text projected as light-DOM children is translatable by the consumer's i18n tooling and by
browser translation; strings trapped in attributes/`aria-label` often are not
([A11Y-002](../accessibility/A11Y-002.md)).

**Do:**

```ts
// Consumer supplies (and translates) the copy via slots.
return html`
  <button part="button-control">
    <slot></slot>
  </button>
`;
```

```html
<ch-button>${t('actions.save')}</ch-button>
```

**Don't:**

```ts
// English hardcoded in the component — untranslatable by consumers.
protected override render() {
  return html`<button>Save changes</button>`;
}
```

See also: [COMP-001](../component-design/COMP-001.md), [A11Y-002](../accessibility/A11Y-002.md), [I18N-002](./I18N-002.md)
