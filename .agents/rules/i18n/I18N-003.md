# I18N-003: Keep civil-date math Gregorian while localizing its presentation

Date components in this library perform civil-date arithmetic using the Gregorian calendar.
Every `Intl.DateTimeFormat` used to format those dates must specify `calendar: 'gregory'` so
locales such as `th-TH`, `ar-SA`, or a `u-ca-*` extension do not silently change the calendar
and disagree with the component's ISO values and arithmetic. Locale-specific ordering, month
names, weekday labels, and numbering remain localized.

Read the effective language with the shared `LocaleController` (`src/controller/locale.ts`). It
resolves the nearest `lang` across shadow-root hosts, caches the normalized locale, observes only
the ancestors that can change it, retargets when that changes, and disconnects symmetrically.
Don't re-implement this with `this.closest('[lang]')`, which stops at the first shadow root
([COMP-017](../component-design/COMP-017.md)).

Normalize user-entered date digits before filtering or parsing them: apply NFKC normalization,
map Arabic-Indic and Extended Arabic-Indic digits to ASCII, then discard remaining non-digits.
For locale week starts, support both `Intl.Locale.getWeekInfo()` and the older `weekInfo`
property when present.

Test at least one locale that defaults to a non-Gregorian calendar, one locale using localized
digits, and a Unicode calendar extension. Also test the fallback week-info API shape.

**Do:**

```ts
new Intl.DateTimeFormat(locale, { calendar: 'gregory', month: 'long', year: 'numeric' });
```

**Don't:**

```ts
// Implicit locale calendar can produce a year/month that conflicts with Gregorian date math.
new Intl.DateTimeFormat(locale, { month: 'long', year: 'numeric' });
```
