# A11Y-009: Honor `prefers-reduced-motion`

Animations and transitions must respect the user's reduced-motion preference. For imperative
animation, gate motion behind the shared `prefersReducedMotion()` helper
(`src/internal/animations.ts`); for CSS `@keyframes`/transitions, wrap or shorten them in a
`@media (prefers-reduced-motion: reduce)` block. Users with vestibular disorders can be made
ill by unrequested motion, so honoring this is a WCAG expectation.

> **Status: aspirational.** A `prefersReducedMotion()` helper exists but currently has no call
> sites, and the library's `@keyframes` (spinner, skeleton, progress-bar) and transition system
> are not yet gated on the media query. Apply this rule to new/changed animations, and prefer
> retrofitting existing ones when you touch them.

**Do:**

```ts
import { prefersReducedMotion } from '../../internal/animations.js';

// imperative: skip/shorten motion
protected animateOpen() {
  if (prefersReducedMotion()) {
    this.visible = true; // jump straight to the end state
    return;
  }
  this.playOpenAnimation();
}
```

```css
/* CSS: neutralize decorative motion when reduced motion is requested */
@media (prefers-reduced-motion: reduce) {
  :host {
    --spinner-animation-duration: 0.01ms;
  }
  .skeleton {
    animation: none;
  }
}
```

**Don't:**

```css
/* Unconditional infinite animation with no reduced-motion escape hatch. */
.spinner {
  animation: spin 1s linear infinite;
}
```
