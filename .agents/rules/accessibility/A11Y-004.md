# A11Y-004: Ship an accessibility test for every component and every state

Accessibility is verified, not assumed. The shared base harness
(`CharmElementTests`) runs an `accessibility` test that asserts
`await expect(el).to.be.accessible()` (axe-based) against every component — so every
component that runs the base harness gets baseline coverage for free
([TEST-001](../testing/TEST-001.md)). Keep that coverage:

- Don't skip or delete the base accessibility test.
- If a component needs axe rule exceptions, scope them narrowly with `ignoredRules` and
  justify them — don't disable the whole check.
- **Scan every state with its own axe test.** The base test only scans the initial render,
  so violations that appear only when a component is open, expanded, invalid, disabled,
  checked, selected, multiple with values, etc. go unnoticed. Register one entry per state
  with `addAccessibilityStates()` so each state fails on its own. Use the shared factories in
  `src/internal/testing/accessibility-states.ts`: `openAccessibilityState()` for dismissibles
  and `formControlAccessibilityStates()` (invalid after interaction, disabled, readonly,
  required). Extending the matching base harness registers these automatically:
  `DismissibleElementTests` adds `open`, and `FormControlTests`/`CoreFormControlTests` add
  the form-control states ([TEST-001](../testing/TEST-001.md)). When you add a
  state-changing property, add its state test in the same PR.
- Add component-specific a11y assertions (focus order, `aria-expanded` toggling, live
  regions) on top of the axe scans.
- Test the component in a realistic semantic parent when its role depends on composition
  (for example, a breadcrumb item inside a labeled navigation/list).
- Every accessibility test must make an assertion. Do not leave placeholder or empty test
  functions, even when axe requires a parent fixture.

**Do:**

```ts
// Base harness assertion (already provided) — keep it running.
await expect(this.component).to.be.accessible({
  ignoredRules: ['aria-allowed-role'], // narrow, justified exception
});
```

```ts
// One axe test per state; each runs on a fresh fixture.
this.addAccessibilityStates({
  ...openAccessibilityState(),
  ...formControlAccessibilityStates(),
  multiple: {
    description: 'when multiple with selected values',
    setup: el => {
      el.multiple = true;
      el.valueAsArray = ['apple', 'banana'];
    },
  },
});
```

**Don't:**

```ts
// Empty tests create false coverage without exercising an accessibility assertion.
it('is accessible', async () => {});

// Toggling several states inside one test hides which state failed, and a default-state
// scan alone misses violations that only render when open/invalid/expanded.
el.open = true;
await expect(el).to.be.accessible();
el.invalid = true;
await expect(el).to.be.accessible();
```
