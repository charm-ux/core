# A11Y-002: Prefer visually-hidden text over `aria-label` for user-facing labels

When a control needs an accessible name that isn't visually shown, prefer rendering the
label as real DOM text with the `visually-hidden` utility class over setting `aria-label`.
Visible-in-the-accessibility-tree text is translatable ([I18N-001](../i18n/I18N-001.md)),
survives when CSS/JS partially fails, and is selectable by more assistive tech than an
`aria-label` string. The `visually-hidden` class ships from the base styles
([STYLE-003](../styling/STYLE-003.md)); toggle it with `classMap`.

Use `aria-label` (bound from a property) for genuinely icon-only controls where there is no
text node to hide — e.g. a dialog's close button. Don't hardcode English strings into
`aria-label` defaults.

**Do:**

```ts
protected radioLabelTemplate() {
  return html`<span
    part="radio-label"
    class=${classMap({ 'radio-label': true, 'visually-hidden': this.hideLabel ?? false })}
  >
    ${this.label ? html`${this.label}` : html`<slot></slot>`}
  </span>`;
}
```

**Don't:**

```ts
// Hardcoded, untranslatable aria-label where a hidden text node would do — and English
// baked into the component.
return html`
  <span aria-label="Select this option"></span>
`;
```
