# A11Y-005: Generate IDs deterministically — static in the shadow root, a module counter for light DOM

ARIA relationships need `id`s, but the library never uses `nanoid`, `crypto.randomUUID`, or
`Math.random`:

- **Shadow-internal targets** — use a plain static string id (e.g. `id="help-text"`). IDs are
  scoped per shadow root, so a hardcoded id can't collide with the page or another instance.
  Reference it directly (`aria-describedby="help-text"`).
- **Light-DOM / slotted targets** (e.g. a slotted trigger referenced by `aria-controls` /
  `aria-labelledby`) — assign an id from a module-level incrementing counter, and only if the
  element doesn't already have one.

**Do:**

```ts
// checkbox.ts — shadow-internal, static id
html`
  <input aria-describedby="help-text" />
  <div id="help-text"><slot name="help-text"></slot></div>
`;

// disclosure.ts — slotted trigger, lazy module-counter id
let disclosureButtonId = 0;

protected setAriaLabels() {
  if (!this.trigger) return;
  this.trigger.setAttribute('aria-expanded', this.open.toString());
  if (!this.trigger.id) {
    this.trigger.id = `disclosure-button-${++disclosureButtonId}`;
  }
}
```

**Don't:**

```ts
// Random/UUID ids are non-deterministic (bad for snapshots/SSR) and unnecessary in shadow DOM.
const id = `help-${crypto.randomUUID()}`;
// Overwriting a consumer-provided id on a slotted element breaks their own references.
this.trigger.id = `disclosure-button-${++disclosureButtonId}`; // without the `if (!id)` guard
```
