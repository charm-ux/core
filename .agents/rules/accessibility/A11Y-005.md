# A11Y-005: Generate IDs deterministically — static in the shadow root, a module counter for light DOM

ARIA relationships need `id`s, but the library never uses `nanoid`, `crypto.randomUUID`, or
`Math.random`:

- **Shadow-internal targets** — use a plain static string id (e.g. `id="help-text"`). IDs are
  scoped per shadow root, so a hardcoded id can't collide with the page or another instance.
  Reference it directly (`aria-describedby="help-text"`).
- **Light-DOM / slotted targets** — assign an id from a module-level incrementing counter, and
  only if the element doesn't already have one. For IDs generated by a composite component,
  capture a unique component-instance ID before asynchronous work and give each child a stable,
  per-instance generated ID; never derive persistent child IDs from the current array index.

An ID reference must resolve in the same tree scope as the referencing element. In particular,
a light-DOM trigger cannot use `aria-describedby` to point at an id rendered only inside a shadow
root. Put referenced descriptions in the trigger's light-DOM tree (or another suitable node in
that same scope), preserve other ID tokens, and remove the component's token when it no longer
applies. Do not create `aria-controls` / `aria-labelledby` references across a shadow boundary;
they do not resolve to the other tree scope.

**Do:**

```ts
// checkbox.ts — shadow-internal, static id
html`
  <input aria-describedby="help-text" />
  <div id="help-text"><slot name="help-text"></slot></div>
`;

// tabs.ts — capture instance identity synchronously, then assign stable child IDs.
let tabsInstanceCounter = 0;
class Tabs {
  protected instanceId = ++tabsInstanceCounter;
  protected generatedTabId = 0;

  protected assignId(tab: HTMLElement) {
    tab.id ||= `tab-${this.instanceId}-${++this.generatedTabId}`;
  }
}
```

**Don't:**

```ts
// Random/UUID ids are non-deterministic (bad for snapshots/SSR) and unnecessary in shadow DOM.
const id = `help-${crypto.randomUUID()}`;
// Overwriting a consumer-provided id on a slotted element breaks their own references.
slottedElement.id = generatedId; // without the `if (!slottedElement.id)` guard
```
