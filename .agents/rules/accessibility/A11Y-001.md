# A11Y-001: Use semantic elements and roles; add ARIA only to fill gaps

Reach for the native element that already carries the right semantics and keyboard behavior
(`<button>`, `<a href>`, `<input>`, `<dialog>`) before building an equivalent from generic
elements plus ARIA. Native semantics are free, correct, and battle-tested; hand-rolled ARIA
widgets are easy to get wrong. Add `role`/`aria-*` only to express state or relationships
the DOM can't (`aria-expanded`, `aria-current`, `aria-controls`), and bind them reactively
to component state.

An overlay's positioning wrapper must not add semantics that misdescribe its content. A menu
popup should expose a menu, a tooltip should expose a tooltip, and a decorative wrapper should
use `role="none"`/`presentation` rather than announcing an unrelated dialog. Dialogs need a
non-empty accessible name; don't point `aria-labelledby` at an empty heading.

**Do:**

```ts
// Real button element — Enter/Space, focus, and role come for free.
const tag = this.href ? literal`a` : literal`button`;
return html`<${tag}
  part="button-control"
  aria-current=${ifDefined(this.current)}
  aria-pressed=${ifDefined(this.pressed)}
>
  <slot></slot>
</${tag}>`;
```

**Don't:**

```ts
// A div "button": no keyboard, no focus, no role — an ARIA reimplementation waiting to rot.
return html`
  <div class="control" @click=${this.handleClick}>
    <slot></slot>
  </div>
`;
```
