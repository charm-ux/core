# A11Y-014: Name the element that carries a composite widget's role

Accessible names do not cross shadow-root boundaries. If a role is rendered inside a component's
shadow root, name the role-bearing element with `aria-labelledby` pointing to translated DOM text
in that same tree scope. For user-facing names, expose the text through a slot and visually hide
the shadow-internal label as needed; do not use `aria-label` or supply a hard-coded English
default ([A11Y-002](./A11Y-002.md), [I18N-001](../i18n/I18N-001.md)).

For relationships such as `aria-controls` and `aria-labelledby`, both the referencing element and
the target ID must be in the same tree scope. Do not emit a cross-shadow ID reference and assume
assistive technology can resolve it. Prefer native structure and state (`aria-expanded` on the
actual button) when a relationship cannot be expressed in the same scope.

**Do:**

```ts
html`
  <span id="tablist-label" class="visually-hidden"><slot name="label">${this.label}</slot></span>
  <div role="tablist" aria-labelledby="tablist-label"><slot></slot></div>
`;
```

**Don't:**

```ts
// Naming the host does not name the internal tablist.
this.setAttribute('aria-label', this.label);
html`
  <div role="tablist"><slot></slot></div>
`;
```
