# A11Y-015: Own keyboard events synchronously and target the element that takes focus

When a component handles a key, it owns that key. Call `preventDefault()` and
`stopPropagation()` **synchronously, before any `await`** (`show()`, `updateComplete`,
`waitForItems()`). Once a handler awaits, the event has already bubbled. An enclosing toolbar,
menu, or dialog then handles the same key: focus jumps, or a submenu toggles twice.

- **Nested composites:** a handler on an item that owns children (a menu item with a submenu, a
  tree item) must check `e.target === this` (or the first entry of `composedPath()`) before
  toggling. Otherwise keys pressed on a child item toggle the owner.
- **Roving items must take focus:** the item that receives `tabindex="0"` and `.focus()` must be
  the element that actually receives keyboard focus and handles the keys. For a `ch-menu` inside
  a toolbar, that's the slotted trigger, not the `ch-menu` host. A host that doesn't delegate
  focus swallows Enter, and the real trigger stays as an extra tab stop.
- **Escape:** once an open overlay has handled Escape, stop propagation so Escape closes only
  that layer. When the overlay is closed or didn't handle the key, let it continue to enclosing
  dialogs (see [A11Y-003](./A11Y-003.md)). Handle Escape through one path, not both an
  element listener and a document listener.
- **Closed widgets:** don't swallow keys you only use while open (Home/End in a closed menu), or
  an enclosing composite can't navigate.

**Do:**

```ts
protected handleKeyDown = (e: KeyboardEvent) => {
  if (e.target !== this || e.key !== keys.Enter) return;
  e.preventDefault();
  e.stopPropagation();          // before any await
  void this.showAndFocus(0, 1); // async work after the event is settled
};
```

**Don't:**

```ts
protected handleKeyDown = async (e: KeyboardEvent) => {
  this.expanded = !this.expanded;
  await this.updateComplete; // the parent menu has already seen the key
  e.preventDefault();
  e.stopPropagation();
};
```

Test the composed case: put the component inside the composite that would also handle the key
(a menu inside a toolbar, a submenu inside a menu) and assert focus and open state with
`sendKeys`.
