# A11Y-003: Manage focus and keyboard interaction

Interactive components must be fully operable by keyboard and manage focus deliberately.

- Extend `CharmFocusableElement` (or `CharmFormControlElement`) for focusable components —
  it sets `delegatesFocus` on the shadow root so focus lands on the right inner control,
  and tracks `hasFocus`/`autofocus` ([CHARM-001](../internal/CHARM-001.md)).
- Support the keyboard interactions expected for the widget's role (Enter/Space to
  activate, arrow keys for composite widgets, Escape to dismiss) and cover them with
  `sendKeys` tests ([TEST-003](../testing/TEST-003.md)).
- Move focus intentionally for overlays (focus the dialog on open, restore it on close),
  and never trap or strand focus.

**Do:**

```ts
export class CoreButton extends CharmFocusableElement {
  // delegatesFocus from the base means the inner <button> receives focus correctly.
}
```

```ts
// Keyboard interaction is real behavior — and it's tested.
await sendKeys({ press: 'Enter' });
expect(clickSpy.callCount).to.equal(1);
```

**Don't:**

```ts
// Focusable-looking div with no keyboard support and no focus delegation.
export class CoreButton extends CharmElement {
  protected override render() {
    return html`
      <div class="control" @click=${this.handleClick}><slot></slot></div>
    `;
  }
}
```
